# 分次核銷

版本 20261124-1。新增使用紀錄時勾選「啟用分次核銷」，適用於一次預支或一次請購、多次核銷。不會轉換或回填任何既有紀錄。既有一般紀錄依原流程計算與操作。

## 使用

1. 新增主紀錄，填原申請總額、學期、科目、用途與請購單號；主紀錄不要求核銷單據。
2. 儲存後，在卡片按「查看／登記明細」。逐筆填日期、用途、金額、核銷單號（選填），上傳單據並確認單據金額。
3. 老師可新增、編輯、刪除自己的未核對明細。經費管理員可處理他人的明細，逐筆核對／解鎖。
4. 第一筆明細建立後，模式永久鎖定，即使刪除所有明細也不能取消。新增前可以取消勾選；未用過的主紀錄也可取消模式後回到一般流程。
5. 管理員核對所有明細後，按「結案並釋回餘額」。確認視窗顯示金額。結案不可重開、重複釋回、新增明細或刪除主紀錄。

原申請總額固定，明細合計不可超過總額。主紀錄不與既有預支分配模組雙重連結，避免重複計算。結案只調整計畫占用額度，不代表已收回現金；實際領款案件仍須另外確認退款。

## 計算

140,000 元主紀錄 + 8,000 元核銷明細：計畫占用仍是 140,000；待核銷 132,000。管理員核對該明細後，已核銷 8,000、未核銷 132,000。結案後占用 8,000、釋回 132,000。主紀錄的原金額保留，沒有改寫成 8,000。

主畫面已核銷／待核對／預估分開計算明細與未使用餘額，三者合計等於目前占用。Excel 主表與使用紀錄明細維持只計一次占用；新增「分次核銷明細」工作表，列原總額、目前占用、結案釋回、逐筆項目及單據連結，參考欄明確標示勿重複加總。會統核對以逐筆明細加尚未結案餘額取代整筆主金額，明細合計不另外加到主金額上。

## 發布

先將本分支的完整 `firestore.rules` 發布到 Firebase 專案 `must-resource-budget-system` 的 Firestore Database → 規則，再合併前端分支。不能貼到 Storage 規則；不需改 Cloudflare Worker。不應先讓一般使用者啟用前端而留著舊規則。

規則採單一明細變動加原子交易：每次只變更一筆，驗證前後金額差額與核對差額，防止偽造合計、超額、自己核對、關案後重複釋回。沒有任何正式資料遷移或測試寫入。
