# 分次核銷細項加入預支分配

版本：20261125-items。

操作與一般預估相同：預支／動支 → 選批次 → 分配活動 → 下拉選擇「主案名｜細項名稱」→ 加入預支分配 → 分配款項給老師。可將同一細項分筆分配給不同老師，但合計不可超過細項金額。老師照舊在「我的領款」確認收到、申報退款，管理員確認退款。

候選項目須與批次同計畫、同學期、同經費項目，主紀錄尚未結案，且細項尚未分配。明細不用先附單據；分配後仍能補上。細項一旦連結預支，其金額與刪除會鎖定，避免款項與核銷內容不一致。尚未領款的分筆可以刪除，全部移除後可解除該細項預支分配，保留主紀錄、原細項與附件。

不新增 expenseRecords、不把主紀錄整筆再次分配。僅新增 advanceAllocations，記錄 expenseRecordId（主紀錄）與 installmentEntryId（細項），並在該細項保存 advanceAllocationId。實際分筆款項仍用既有 advancePayouts；收款確認、退款與老師權限沿用既有流程。

預支現金分配與計畫經費占用分開：計畫仍由主紀錄占用一次，細項發款不再扣一次計畫經費。細項的現金退款只修正發款帳，不自動改寫原申請總額或核銷金額。細項不走一般使用紀錄的追加功能；金額有誤時先處理未領款分配並解除，再編輯細項。

規則以同一交易驗證關聯建立／解除，拒絕單邊綁定、重複綁定、跨計畫、跨學期、錯誤科目、金額不符，以及已綁定後偷改金額或刪除。預支承辦人仍限本人批次與本人主紀錄；老師只確認自己的分筆領款。

發布順序：先由專案擁有者發布本分支完整 firestore.rules，再合併前端。既有活動／使用／預支資料不回填、不遷移；沒有以正式紀錄測試。
