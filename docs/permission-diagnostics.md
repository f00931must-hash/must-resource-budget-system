# 權限診斷與修復（20261121-1）

經費管理員登入後，上方分頁新增「權限診斷」。一般老師不顯示帳號管理分頁；發生錯誤時可使用右下角「查看錯誤與排除方式」更新自己的登入、下載本分頁摘要。

## 可以自行處理

1. **帳號未啟用或角色錯誤**：輸入老師完整 Email → 檢查帳號 → 確認角色與啟用狀態 → 儲存帳號授權。只有按儲存且確認後，才更新該筆既有 users 帳號文件；不改經費紀錄、不建立 Google 帳號。設定相同不寫入，別人已更改過的設定不覆蓋，不能在這裡停用／降級自己的管理員資格。
2. **登入仍停留在舊資格**：按「更新我的登入狀態」，先保留未儲存內容，再重新整理。這個動作不重送剛才失敗的操作。
3. **附件／通知部署版本不同**：手動按「檢查版本」，僅 GET 兩個 Worker 的 health。無法取得時標示「無法確認」，不能直接認定是權限或網路問題。比對的是版次，不是所有功能的實測。
4. **紀錄鎖定或連結預支**：使用紀錄卡片的「診斷」或輸入紀錄編號，手動讀取該筆狀態，顯示應回使用紀錄解鎖、或走預支的追加／退款流程。本頁不直接改紀錄、解鎖、解除分配或改金額。
5. **留下可判讀的錯誤**：收集本分頁已顯示的錯誤提示和未處理例外，最多 20 筆，記錄固定分類、固定階段、時間與「是否明確提示已儲存」。下載 JSON 可交給管理員或維護者，不必只靠截圖。

## 不會假裝能修好的情況

- JavaScript 網頁無法讀取 Firebase Console 實際已發布的規則版本。本頁明確標示規則版本未驗證，提供後台與本版完整規則連結；不會把「可讀帳號」當成「可寫全部資料」。
- 真正的規則缺陷、程式送錯欄位、服務端錯誤仍需修改程式或規則。沒有一鍵全部放行、代貼規則、擅自新增管理員或靜默提升權限功能。
- 沒有自動寫入「測試紀錄」。讀取檢查成功不代表所有寫入一定成功。
- 這不是跨裝置的操作紀錄系統。管理員看不到其他老師電腦上的錯誤；老師可自行下載摘要交給管理員。沒有上傳錯誤紀錄到 Firestore，也沒有增加付費日誌服務。

## 隱私與讀取量

- 摘要只存目前分頁的 sessionStorage，依登入 UID 分開，最多 20 筆；切換帳號會切換摘要。沒有保存原始錯誤文字、Email、姓名、用途、金額、紀錄 ID、附件內容／路徑或登入 Token。
- 載入模組只讀一次目前登入者帳號；不掃描全部老師、全部計畫或經費紀錄，沒有資料庫輪詢。
- 檢查指定帳號／紀錄時才個別讀取。儲存授權時會重新驗證目前管理員，並在 transaction 內再次核對自己的資格和目標帳號是否變更。
- Firebase Rules 仍是實際授權依據；隱藏按鈕不等於取得後端權限。其他老師即使自行顯示隱藏的頁面，也不能執行管理員儲存。

## 測試

```sh
npm install --prefix .emulator --no-save jsdom@26
node --test tests/permission-diagnostics.test.mjs tests/permission-diagnostics-ui.test.mjs
python scripts/test-permissions.py
```

測試涵蓋唯讀啟動、管理員修改既有帳號、一般老師被拒絕、停用／降級自己被拒絕、資格在交易期間變更、目標設定過期、重複儲存不寫入、摘要去識別化、頁面 UI，以及實際 account service 對本機 demo emulator 的寫入。測試時所有人員與經費資料皆為隔離假資料，沒有更動正式紀錄。

只需部署前端，不變更 firestore.rules 或兩個 Worker。既有規則已允許經費管理員維護 users 文件；若正式規則仍不是目前重整版，帳號維護可能仍被正式規則拒絕，本頁會保留此限制而不繞過。
